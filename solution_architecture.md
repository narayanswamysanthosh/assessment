# Solution Architecture: 30-Day Readmission Triage

## 1. System overview

The project generates synthetic admissions, trains and validates a readmission-risk model, produces holdout predictions, and exposes scoring through a local FastAPI service. A separate React/Vite application provides the care-management interface.

```text
synthetic_data_generator/data_generator.py
  └── synthetic_data_generator/data/
      ├── train_admissions.csv       (60,000 rows; 2021–2023)
      └── holdout_admissions.csv     (8,000 rows; Jan–Mar 2024)
                    │
                    ▼
code/train_and_score.py
  ├── uses backend/readmission_features.py
  ├── validates on 2023 after training on 2021–2022
  ├── saves code/artifacts/readmission_model.joblib
  ├── saves code/artifacts/validation_metrics.json
  └── writes predictions.csv (one score for each holdout admission)
                    │
                    ▼
backend/app.py
  ├── GET  /health
  ├── POST /score/one
  ├── POST /score/batch
  └── GET  /call-list
                    ▲
                    │ HTTP (VITE_API_BASE_URL)
                    ▼
frontend/lakeshore-ops/
  └── React/Vite dashboard and single-patient entry view
```

## 2. Components

### Synthetic data: `synthetic_data_generator/`

- `data_generator.py` writes the training and holdout CSVs to `synthetic_data_generator/data/`.
- The generated data include repeat patients, missing labs/vitals, date/weekday inconsistencies, and injected invalid values for testing cleaning logic.
- These are **synthetic data and simulated audit cases**, not findings from a real EHR.

### Feature cleaning and training: `backend/` and `code/`

- `backend/readmission_features.py` defines `HospitalFeatureCleaner`, used by the training pipeline and embedded in the saved scikit-learn model pipeline for inference.
- `code/train_and_score.py` performs the temporal train/validation split, compares Logistic Regression and HistGradientBoosting candidates, refits a model, saves artifacts under `code/artifacts/`, and writes `predictions.csv`.
- Cleaning recomputes length of stay and weekend status from dates, handles implausible values as missing, excludes post-discharge call information from model features, and derives utilization/lab indicators.
- **Model selection:** The training script selects by highest 2023 Precision@5%, then lowest Brier score, then lowest ECE. With the recorded metrics this selects Logistic Regression; see `decision_log.md`.

### Backend service: `backend/app.py`

- FastAPI validates scoring inputs with Pydantic, loads the model from `code/artifacts/readmission_model.joblib`, and reads the holdout from `synthetic_data_generator/data/holdout_admissions.csv`.
- `GET /health` reports service/model status.
- `POST /score/one` scores one admission; `POST /score/batch` accepts 1–25,000 admissions and processes them in chunks of 5,000.
- `GET /call-list` ranks holdout admissions and returns a capacity-limited list with plain-language review cues. The API defaults to 5% capacity and accepts 1–25%; the dashboard slider defaults to 5% and lets users select 1–15%. The list can also be filtered by site and discharge week.
- `API_HOST`, `API_PORT`, and `CORS_ORIGINS` configure the Uvicorn bind address, port, and allowed frontend origins.

### Frontend: `frontend/lakeshore-ops/`

- The React/Vite application provides the weekly ranked call list, staffing-capacity control, site/week filters, score explanations, and a visible risk disclaimer. It also provides single-patient entry, which calls `POST /score/one`.
- Set `VITE_API_BASE_URL` in `.env.local` (see `.env.example`) to point the frontend to the backend.
- The frontend is a separate Vite application. Its production build is written to `frontend/lakeshore-ops/dist`; **the current FastAPI app does not mount or serve that build**. Run the Vite development server separately during local use.

## 4. Local run sequence

Run commands from the project root unless noted.

1. Generate synthetic data, compare models, fit the selected model, and regenerate the holdout predictions:
   `python code/run_assessment.py`
2. Start the API:
   `python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000`
3. In a separate terminal, configure `frontend/lakeshore-ops/.env.local` with `VITE_API_BASE_URL=http://localhost:8000`, then run:
   `cd frontend/lakeshore-ops`
   `npm run dev`

Build and lint the frontend from `frontend/lakeshore-ops` with `npm run build` and `npm run lint`.
Run the focused backend test with `python -m unittest discover -s tests`.
